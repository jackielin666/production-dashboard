# 生產鍋數月報 — 分析邏輯規格

本文件記錄月報的**完整判定規則**，讓邏輯不依賴任何單一對話或人員。
程式實作：`tools/monthly_report.py`；門檻設定：`tools/report_config.json`。

## 目的與取向

公司為**業務導向、接單式生產**。生產鍋數直接反映業務量與營收：
> 某品項鍋數明顯下降 → 出貨量下降 → 接單量下滑 → **營收風險**（主力品項尤其關鍵）。

因此本報告聚焦**業務量**，不做製成率／品質分析（由「產品工時及製成率統計系統」負責）。

## 資料來源

`data/latest.xlsx` →「資料總表」。使用欄位（0-based）：

| 欄 | 名稱 | 用途 |
|----|------|------|
| 0 | 日期 | 期間切分 |
| 1 / 2 | 料號 / 品項 | 品項識別 |
| 3 | 鍋數(P) | **業務量主指標** |
| 8 | 半成品重量(KG)(實際) | **交叉驗證指標** |
| 20 | 刪除 | 有值即整列排除 |

未使用：達成率、工時、良率、不良品、重工、領料時間等（屬另一系統範圍）。

## 基礎彙總規則（與儀表板 `buildDashboardData` 一致）

- 排除「刪除」欄有值的列；排除品項為 `#N/A` 或空白的列。
- 品項 key＝料號；若料號為 `-`、`專案`、`研發` 或空，改用 `料號__品項`。
  → **同名但不同料號視為不同品項**，不合併。
- 類別：品項名稱含「花生」→ 花生類，否則 → 果醬餡類。
- 月彙總四捨五入採 Python 的「四捨六入五成雙」。

## 資料完整性

- 只有**最新月**可能尚未補齊：若其筆數 < 其餘月份中位數的 **90%**，判定未補齊。
  指定該月產生報告時會被擋下（可用 `--allow-incomplete` 強制產出）。
- **歷史月份視為已完整**。其筆數本來就會隨工作天數／淡旺季浮動 ±20%，
  僅在明顯異常（< 中位數 **50%**）時提示，不阻擋。

## 分析項目

### 1. 整體業務量
本月總鍋數、總重量(kg)、生產品項數；環比（vs 上月）、同比（vs 去年同月）、
YTD（1月~本月累計 vs 去年同期）。

### 2. 接單下滑警示（核心）

**觸發條件**（任一成立）：
- 環比降幅 ≤ −`decline_pct`% 且 **上月** 鍋數 ≥ `min_scale_pots`
- 同比降幅 ≤ −`decline_pct`% 且 **去年同月** 鍋數 ≥ `min_scale_pots`

**排序**：依流失鍋數絕對值（取環比／同比中流失較大者）由大到小 —— 讓大品項先浮現。

**雙軌交叉判讀**（以流失較大的基準比較重量變化，避免誤報）：

| 重量變化 | 判讀 | 意義 |
|----------|------|------|
| ≤ −`decline_pct`% | 🔴 實質接單下滑 | 產出同步下降，確為業務量減少 |
| −`decline_pct`% ~ −`kg_flat_pct`% | 🟡 部分下滑 | 部分反映在產出上 |
| > −`kg_flat_pct`% | ⚪ 批量調整 | **鍋數降但重量持平＝改大批量生產，不是接單下滑** |
| 無重量資料 | － | 無法交叉驗證 |

> 一「鍋」是一個生產批次。若改成大批量生產，鍋數會下降但實際產出不變。
> 這是本報告最重要的防誤報機制，**不要移除**。

**主力品項標記**：以**前 12 個月累計鍋數**排名前 `top_n` 者為主力
（用前 12 個月而非本月，才不會因為本月衰退就跌出主力名單）。

### 2.5 品項註記（item_overrides）

某些品項的變動不代表接單狀況，硬套通用規則會產生誤報。這類品項以**料號**註記在
`tools/report_config.json` 的 `item_overrides`，新增品項只要加一行，不需改程式。

| status | 意義 | 影響 |
|--------|------|------|
| `discontinued` | 已下市產品 | **完全排除**於接單下滑警示與斷單警示之外，不參與燈號判定 |
| `seasonal_oem` | 季節性代工品項 | **不列入主力品項**、**不觸發燈號**；仍出現在清單中但加註標籤；並另計「排除季節性代工後」的總量 |

目前已註記：
- `C1020` 天天開心草莓餡4.5KG —— 已下市（計畫性下市，非接單流失）
- `D0390` 化應子(1*2.5KG) —— 季節性代工（量體大且間歇，非主力型產品）

**「排除季節性代工後」的總量**：代工品項量體大又間歇（化應子曾單月占全廠三成、隔月歸零），
會讓月度總數劇烈起伏。報告因此另計一組排除後的鍋數與環比／同比，反映本業真實表現；
燈號的同比判定也改用這組數字，避免代工的有無誤觸紅燈。

被註記的品項會列在報告頁尾，保持透明，不會無聲消失。

### 3. 斷單警示
前 `dormant_lookback`(6) 個月中有 ≥ `dormant_min_active`(3) 個月正常生產、
且平均月鍋數 ≥ `min_scale_pots`，但**本月完全沒有生產**。

斷單是比「衰退」更嚴重的獨立類別，**已列為斷單者不再重複列入衰退警示**，兩份清單互斥。

### 4. 成長品項
本月鍋數 > 0 且較上月或去年同月增加，依增加量取前 `top_n`。

### 5. 新品 / 回流
- 新品：本月之前從未生產過。
- 回流：前 3 個月皆為 0，本月恢復生產。

### 6. 集中度
本月前 `top_n` 大品項的鍋數、佔比與累積佔比（Pareto）。

### 7. 類別表現
果醬餡類 vs 花生類的鍋數／重量，環比與同比。

### 8. 季節性判讀
- 同月份跨年度並列（如 2024/8、2025/8、2026/8）。
- 計算過去年度「同一個月份轉換」的平均環比，與本月環比比較：
  - 本月環比不比常態差 5 個百分點以上 → 屬季節性常態
  - 差 5 個百分點以上 → 非單純季節性因素

### 9. 綜合燈號

| 燈號 | 條件 |
|------|------|
| 🔴 需注意 | 總鍋數同比 ≤ −`decline_pct`%、或有主力品項實質衰退、或有主力品項斷單 |
| 🟡 觀察／持平 | 有衰退訊號但未涉及主力品項，或總量變化不大 |
| 🟢 表現良好 | 總量環比與同比皆成長，且無主力品項警示 |

## 輸出

- `reports/YYYY-MM.html` — 自足式報告（可分享）
- `reports/YYYY-MM.json` — 全部計算結果（撰寫總評時引用）
- `reports/index.html` — 歷月索引

連結：`https://jackielin666.github.io/production-dashboard/reports/YYYY-MM.html`

## 已知限制

- **資料中沒有客戶／訂單欄位**，因此無法做客戶層級的流失分析（業務上最有價值的一種）。
  若日後 Excel 匯出能加入「客戶」欄，可再擴充此報告。
- 同名不同料號的品項會分開統計；報告以料號區分，判讀時請留意。
- 年度相關邏輯目前以資料內實際年份運算，不受儀表板 2024–2026 寫死的限制。

## 驗證方式

報告數字必須與已驗證的儀表板一致。基準例（2026/06）：
總鍋數 **2,556**、生產品項 **49**、上月 2,600、去年同月 3,051。
修改彙總規則時，兩邊都要重新對齊。
