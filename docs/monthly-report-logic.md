# 生產鍋數月報 — 分析邏輯規格

本文件記錄月報的**完整判定規則**，讓邏輯不依賴任何單一對話或人員。
程式實作：`tools/monthly_report.py`；門檻設定：`tools/report_config.json`。

## 目的與取向

公司為**業務導向、接單式生產**。生產鍋數直接反映業務量與營收：
> 某品項鍋數明顯下降 → 出貨量下降 → 接單量下滑 → **營收風險**（主力品項尤其關鍵）。

因此本報告聚焦**業務量**，不做製成率／品質分析（由「產品工時及製成率統計系統」負責）。

## 資料來源

`data/latest.xlsx` →「資料總表」。使用欄位（0-based）：

| 欄 | 名稱 | 用途 |
|----|------|------|
| 0 | 日期 | 期間切分 |
| 1 / 2 | 料號 / 品項 | 品項識別 |
| 3 | 鍋數(P) | **業務量主指標** |
| 8 | 半成品重量(KG)(實際) | **交叉驗證指標** |
| 20 | 刪除 | 有值即整列排除 |

未使用：達成率、工時、良率、不良品、重工、領料時間等（屬另一系統範圍）。

## 基礎彙總規則（與儀表板 `buildDashboardData` 一致）

- 排除「刪除」欄有值的列；排除品項為 `#N/A` 或空白的列。
- 品項 key＝料號；若料號為 `-`、`專案`、`研發` 或空，改用 `料號__品項`。
  → **同名但不同料號視為不同品項**，不合併。
- 類別：品項名稱含「花生」→ 花生類，否則 → 果醬餡類。
- 月彙總四捨五入採 Python 的「四捨六入五成雙」。

## 資料完整性

- 只有**最新月**可能尚未補齊：若其筆數 < 其餘月份中位數的 **90%**，判定未補齊。
  指定該月產生報告時會被擋下（可用 `--allow-incomplete` 強制產出）。
- **歷史月份視為已完整**。其筆數本來就會隨工作天數／淡旺季浮動 ±20%，
  僅在明顯異常（< 中位數 **50%**）時提示，不阻擋。

## 分析項目

> **規則版本**：以下為 2026/09 起適用的規則（2026-09 與 Jackie 哥討論後定案）。
> 2026/06~2026/08 已發布的月報維持原樣，不重新產生。

### 0. 指標口徑
- **鍋數為主、重量為輔。** 重量會受製程條件改變影響，只作參考，不用來排除或降級警示。
- 月報為「整月 vs 整月」；期中預覽為「同期 vs 同期」（見第 13 節）。

### 1. 整體業務量
本月總鍋數、總重量(kg)、生產品項數；環比（vs 上月）、同比（vs 去年同月）。
KPI 卡片以**全廠整體**呈現（含季節性代工），另在總評區附「排除季節性代工後」的數字。

### 2. 接單下滑警示（核心）

**觸發條件**（任一成立）：
- 環比降幅 ≤ −`decline_pct`% 且 **上月** 鍋數 ≥ `min_scale_pots`
- 同比降幅 ≤ −`decline_pct`% 且 **去年同月** 鍋數 ≥ `min_scale_pots`

**流失鍋數**：取環比／同比中流失較大者。

**分級**（只看鍋數）：

| 等級 | 條件 | 呈現 |
|------|------|------|
| **A** | 主力品項（不設門檻） | 置頂，總評必須點名 |
| **B** | 非主力，流失 ≥ 本業總鍋數 × `b_grade_pct`%（預設 1%，約 30 鍋；隨淡旺季自動調整） | 表格 |
| **C** | 其餘 | 預設收合 |
| **註** | 季節性代工品項 | 另列，不參與分級、不進圖表 |

「本業總鍋數」＝本月總鍋數扣除季節性代工品項。

**重量參考欄**：列出重量變化（同步下降／小幅下降／持平或增加），**僅供參考，不影響分級**。

**主力品項標記**：以**前 12 個月累計鍋數**排名前 `top_n` 者為主力
（用前 12 個月而非本月，才不會因為本月衰退就跌出主力名單）。

### 2.5 品項註記（item_overrides）

某些品項的變動不代表接單狀況，硬套通用規則會產生誤報。這類品項以**料號**註記在
`tools/report_config.json` 的 `item_overrides`，新增品項只要加一行，不需改程式。

| status | 意義 | 影響 |
|--------|------|------|
| `discontinued` | 已下市產品 | **完全排除**於接單下滑警示與斷單警示之外，不參與燈號判定 |
| `seasonal_oem` | 季節性代工品項 | **不列入主力品項**、**不參與警示分級**（另列「註」）、**不觸發燈號**；並另計「排除季節性代工後」的總量與 YTD |

目前已註記：
- `C1020` 天天開心草莓餡4.5KG —— 已下市（計畫性下市，非接單流失）
- `D0390` 化應子(1*2.5KG) —— 季節性代工（量體大且間歇，非主力型產品）

**「排除季節性代工後」的總量**：代工品項量體大又間歇（化應子曾單月占全廠三成、隔月歸零），
會讓月度總數劇烈起伏。報告因此另計一組排除後的鍋數與環比／同比，反映本業真實表現；
燈號的同比判定也改用這組數字，避免代工的有無誤觸紅燈。

被註記的品項會列在報告頁尾，保持透明，不會無聲消失。

### 3. 斷單警示
前 `dormant_lookback`(6) 個月中有 ≥ `dormant_min_active`(3) 個月正常生產、
且平均月鍋數 ≥ `min_scale_pots`，但**本月完全沒有生產**。

- 顯示**最後生產月**（及當月鍋數）與**連續未生產月數**（含本月）。
- 連續未生產 ≥ `dormant_lost_months`(3) 個月 → 標為「**疑似流失**」。
- 斷單是比「衰退」更嚴重的獨立類別，**已列為斷單者不再重複列入衰退警示**，兩份清單互斥。

### 4. 資料異常 — 請製造單位說明
鍋數與重量不匹配時**只點出、不推測原因**，請製造單位說明。條件（本月鍋數 ≥ `anomaly_min_pots`）：

1. 有鍋數、重量為 0（正式月報：月份結束後仍有批次未填重量；每鍋重量只用已填重量的批次計算）；
2. 有 ≥ `anomaly_min_history`(3) 個月歷史：每鍋重量偏離該品項前 12 個月中位數 ±`anomaly_dev_pct`(50)% 以上；
3. 歷史不足（新品）：每鍋重量低於全廠平均的 `anomaly_new_low_pct`(20)% 或高於 `anomaly_new_high_pct`(300)%。

重量常於事後補登：本月有重量的鍋數占比 < `anomaly_kg_coverage_pct`(50)% 時，視為
「重量尚未填入」，暫停此檢查並在報告上註明（重量 KPI 顯示「—」）。

例：化應子 2026/07 做了 1,206 鍋、重量僅 382 kg（每鍋 0.3 kg，全廠平均約 128 kg）→ 列入。

### 4.5 名詞說明區塊
報告在總評下方有可展開的「📖 名詞說明」，說明警示觸發條件、A／B／C 級、斷單、燈號，
並列出**本期主力品項清單**（前 12 個月累計鍋數、占比、本月鍋數），供會議中回答
「什麼是 A 級」「主力品項有哪些」這類問題。「本月產量前 10 大」與「主力品項」是不同清單，已分開命名。

### 5. 上期追蹤
依**現行規則**重算上月，列出上月的 A／B 級衰退、斷單、資料異常品項，在本月的狀態：

| 類型 | 狀態判定 |
|------|----------|
| 衰退 | 本月 ≥ 當時比較基準 90% → 已恢復；本月 0 → 轉為斷單；較上期 +10% 以上 → 回升中；較上期 −10% 以上 → 持續下滑；其餘 → 未改善 |
| 斷單 | 本月有生產 → 恢復生產；否則 → 持續斷單（連續 N 月） |
| 資料異常 | 本月仍符合條件 → 仍異常；本月未生產 → 無法確認；否則 → 已正常 |

需處理的（紅）排在最前面。

### 6. 環比變動拆解（瀑布圖）
上月總鍋數 → 減少最多的 `waterfall_items`(5) 項 → 其他減少 → 其他增加 → 增加最多的 5 項 → 本月總鍋數。
縱軸不從 0 開始，以便看清增減。

### 7. 年度累計（YTD）
1 月至本月累計鍋數，今年 vs 去年同期。**有季節性代工品項時，主數字排除代工**，
並註明被排除的品項與鍋數、以及「含代工」的數字，讓讀者兩者都看得到。
圖表：今年（排除）、去年（排除）、今年（含代工，虛線）三條累計線。

### 8. 成長品項
本月鍋數 > 0 且較上月或去年同月增加，依增加量取前 `top_n`。

### 9. 新品 / 回流
- 新品：本月之前從未生產過。
- 回流：前 3 個月皆為 0，本月恢復生產。

### 10. 集中度
本月前 `top_n` 大品項的鍋數、佔比與累積佔比（Pareto）。

### 11. 類別表現
果醬餡類 vs 花生類的鍋數／重量，環比與同比。

### 12. 季節性判讀
- 同月份跨年度並列；**資料不完整的月份（筆數 < 中位數 50%，或整月缺漏）不列入**，並註明。
  目前 2024/07 僅 28 筆、2024/08 無資料，因此 7、8 月的樣本只有 2025 年。
- 計算過去年度「同一個月份轉換」的平均環比，與本月環比比較：
  - 本月環比不比常態差 5 個百分點以上 → 屬季節性常態
  - 差 5 個百分點以上 → 非單純季節性因素
- 報告註明樣本年數；**少於 3 年標示「僅供參考」**。

### 13. 綜合燈號

| 燈號 | 條件 |
|------|------|
| 🔴 需注意 | 本業同比 ≤ −`decline_pct`%、或主力品項斷單（連續 ≥ `red_core_dormant_months` 月）、或 A 級（主力）流失合計 ≥ 本業總鍋數 × `red_core_loss_pct`% |
| 🟡 觀察 | 有 A 級（主力）衰退，但未達紅燈 |
| 🟡 持平 | 無主力警示，但總量小幅衰退 |
| 🟢 表現良好 | 本業環比與同比皆未衰退，且無主力品項警示 |

`red_core_loss_pct` 以 2025/01~2026/08 共 20 個月回測校正：

| 門檻 | 20 個月中紅燈月數 |
|------|------|
| 5% | 19（燈號失去鑑別力） |
| 10% | 15 |
| 15% | 12 |
| **15% ＋ 主力連續斷單 ≥ 2 月（採用，2026-09 定案）** | **10** |

主力品項偶爾空一個月（如蜜桔皮）屬常態，因此主力斷單需連續 ≥ 2 個月才觸發紅燈
（`red_core_dormant_months` = 2）；單月斷單仍會列在斷單警示中。

### 14. 期中預覽（月底廠務會議用）
本月尚未結束時先看月報內容。指令加 `--preview`，輸出 `reports/YYYY-MM-preview.html`。

- **比較口徑改為「同期」**：本月 1~D 日 vs 上月 1~D 日 vs 去年同月 1~D 日（D＝資料最後一天，
  或 `--asof` 指定）。若 D 已是月底，則為整月比較。
- **不做任何推估**：報告只呈現實際值（2026-09 決議：推估值準確度難以判斷，不列入）。
- 「本月 0 鍋」的常態品項改稱「**截至目前尚未生產**」，**不算斷單、不觸發燈號**。
- 燈號標「（暫定）」；頁首有橘色橫幅提醒「本月尚未結束，非正式月報」；資料少於 10 天時加註波動提醒。
- 上期追蹤改列「上月同期」與「本月至今」兩個實際值：本月至今已達當時比較基準 90% 以上 → 已恢復；
  較上月同期 ≤ −10% → 持續下滑；≥ +10% → 較上月同期增加；其餘 → 持平；0 → 本月尚未生產。
- **重量補登時間差**：月中常有批次尚未填重量。預覽時這些批次**不列入資料異常**，
  每鍋重量只用已填重量的批次計算；重量 KPI 顯示「補登中（已填 X%），暫不比較」，
  橫幅列出未填重量的鍋數與日期。正式月報（月份已結束）仍有未填重量的批次，才列為「有鍋數、無重量」。
- **資料空窗偵測**：本月連續 ≥ `preview_gap_days`(5) 天沒有任何生產紀錄時，橫幅提示
  「請確認是停產還是資料尚未登錄」（過去一年正常月份最長 4 天；農曆年除外）。
- 索引頁以橘色虛線框列出；同月份的正式月報產生後，預覽即不再列出。

## 輸出

- `reports/YYYY-MM.html` — 自足式報告（可分享）
- `reports/YYYY-MM-preview.html` / `.json` — 期中預覽（每次產生覆蓋同一檔）
- `reports/YYYY-MM.json` — 全部計算結果（撰寫總評時引用）
- `reports/index.html` — 歷月索引

連結：`https://jackielin666.github.io/production-dashboard/reports/YYYY-MM.html`

## 已知限制

- **資料中沒有客戶／訂單欄位**，因此無法做客戶層級的流失分析（業務上最有價值的一種）。
  若日後 Excel 匯出能加入「客戶」欄，可再擴充此報告。
- 同名但不同料號的品項（含 `-1` 改版料號）一律視為獨立品項，分開統計，不做任何提示或合併。
- 年度相關邏輯目前以資料內實際年份運算，不受儀表板 2024–2026 寫死的限制。

## 驗證方式

報告數字必須與已驗證的儀表板一致。基準例（2026/06）：
總鍋數 **2,556**、生產品項 **49**、上月 2,600、去年同月 3,051。
修改彙總規則時，兩邊都要重新對齊。
